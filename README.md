# Tail-Influence Sampling (TIS)

Code, configurations, frozen artifacts, and results for
*Tail-Influence Sampling for CVaR Policy Evaluation*.

TIS allocates a fixed budget of conditional queries across state--action
kernels to estimate a fixed policy's categorical CVaR. It learns each
kernel's influence on the root tail estimate from a pilot, accounting for
kernel reuse across Bellman stages, and allocates main samples in
proportion; an occupancy-anchored variant safeguards against pilot
underestimation.

## Layout

| Path | Contents |
|---|---|
| `src/tis/` | Library: categorical Bellman engine, influence solver, allocation, tabular runner, `llm_study/` and `finqa/` study pipelines |
| `configs/` | One JSON per experiment; every seed, budget, method list, and floor is recorded here |
| `frozen/` | Pre-registered artifacts: calibrated kernels, question banks/panels, freeze records and declarations (written before the runs they gate) |
| `results/` | Committed outputs: per-run `summary.csv`/`raw.csv`/`manifest.json`, plus analysis JSONs |
| `scripts/` | Analysis and figure generation; see `scripts/README.md` for a per-script index |
| `tests/` | Unit tests (numerical identities, protocol invariants, determinism) |
| `figures/` | Paper figures, regenerated by the scripts below |

## Setup and tests

Python 3.10+ with the pinned scientific stack:

```bash
python -m pip install -r requirements-lock.txt -e .
PYTHONPATH=src python -m unittest discover -s tests   # 42 tests
```

## Quick start

A deterministic small run plus verification (about a minute):

```bash
tis run --config configs/public_quick.json
tis verify-results --directory results/public_quick
```

The full tabular runs are `configs/public_paper.json` and
`configs/replacement_paper.json` (hours on one CPU; `make paper`,
`make replacement-paper`). Each run directory records its configuration,
package versions, and file hashes in `manifest.json`, and the runner
refuses to overwrite existing outputs without `--overwrite`. All random
streams derive from the recorded master seed, environment, budget,
replication, and stage, so reruns reproduce the committed results
(verified byte-identical for both tabular runs).

## Directory naming

The LLM-study configs and result directories encode the generator and
method panel in their names: `robustness`/`robustness2` are Phi-4-mini
and Granite-4.2-8B, `scale1`/`scale2`/`scale3` are Mistral-24B,
Qwen3-32B, and GLM-4-32B (the unmarked name is the primary Qwen3-4B);
`closed` is the main closed-grid panel, and `ext`, `anchored`, and
`rollout` are the learned-baseline, anchored-TIS, and rollout panels on
the same generator. FinQA names carry the workflow (`ordinary`,
`unitcheck`), the generator (`_phi`; unmarked is Qwen3-4B), and the
phase (`dev`, `heldout`); `_ua` is the unit-aware metric variant and
`_b48` the 400/800 budget extension.

## Study pipelines

The LLM studies separate a one-time GPU calibration (frozen conditional
kernels under `frozen/`) from CPU-only simulation, which is all this
repository needs to reproduce every reported number. The
`scripts/run_*.sh` launchers document how the calibrations and simulation
campaigns were executed; they are not required for reproduction.


## Result validity

Environments are implemented locally from the versioned public dynamics;
population constants are asserted in the test suite. Result directories
are validated with `tis verify-results`. The controlled-MRP and inventory
instances follow the anti-tuning rule in
`specs/replacement_instances.json`.

## Large artifacts

A few per-run files exceed repository size limits (some `allocations.csv`,
FinQA raw draws); their SHA-256 checksums are recorded in
`results/external_artifacts.json`. Every reported number reproduces from
the committed artifacts alone.
